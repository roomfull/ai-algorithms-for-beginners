# 第08章：剪枝、量化与可验证的误差

先完成矩阵、绝对值、排序、平均值和梯度基础。本章把已经给定的一小组权重做数值变换；不训练大模型，不需要GPU，全部答案用标准库。目标是把“压缩”拆成能手算、能测试的步骤，并理解数值变化与实际存储/运行速度之间的区别。

## 1. 权重、位数和数据体积

神经网络中的权重是参与乘法的参数。例如 `y=w1*x1+w2*x2+b`，w1,w2,b就是需要保存并更新的数。矩阵权重可表示很多输出通道，每行看作一个整体是一种简化的结构化剪枝模型。

1字节（byte）等于8位（bit）。FP32每项32位即4字节，INT8每项8位即1字节。100个值的数据部分理论上从400字节变成100字节；额外的scale、零点与文件元数据会改变最终文件大小。Python的普通int与float对象不是恰好1字节或4字节，本章输出整数只是表示量化码，不测Python对象真实内存。

剪枝减少被使用的连接或结构；量化用更少的整数码近似权重。两者可能结合，但都需要后续存储格式和计算实现配合，才能获得实际收益。

## 2. 阈值剪枝与按数量剪枝

阈值剪枝看 `abs(x)<t`，符合条件才置零。t=1时 `[0.5,-1,2]`变成`[0,-1,2]`，等于阈值的-1保留。阈值法不能预先保证恰好剪几项。

按比例剪枝先算 `k=floor(n*ratio)`，再剪掉最小绝对值的k个位置。比如 `[3,1,0,-1,2]`，ratio=0.4，k=2，排序依次是索引2、1、3、4、0，剪索引2和1，得到`[3,0,0,-1,2]`。绝对值相同按索引小者先剪，才能有确定答案。

掩码（mask）记录动作：1保留、0剪掉。原值已是0但未选中时，掩码仍可能为1，因此“零元素数”不等于“本轮选择的剪枝数”。也不能把稠密数组中的值改为0就说文件自动变小；若仍按n项FP32保存，数据部分仍是4n字节。

十进制比例要精确求floor：数学上100×0.29=29，但二进制float表示及乘法可能略小于29。Python标准库 `Fraction('0.29')`表示29/100；`int(100*Fraction('0.29'))`精确得到29。先读成float再转Fraction保留的是浮点近似，无法恢复原十进制契约。

## 3. 行L1范数与结构化选择

一行 `[1,-2]`的L1范数是 `abs(1)+abs(-2)=3`，不是和-1，也不是L2范数sqrt(5)。P073保留L1最大的keep行；同范数较小索引优先保留。

三行 `[1,-2]`、`[3,0]`、`[2,2]`范数3、3、4，keep=2选择行2与行0。选择可按范数排序，但结果必须恢复原行顺序，输出行0再行2。掩码为1,0,1。用行级删除可能改变矩阵形状与后续层连接，需要整个网络一起调整；本题只模拟明确的行选择，不承诺自动得到可运行的压缩网络。

小数范数也可能数学上并列：0.1+0.2与0.3应该相等。这里用Fraction计算行范数后排序，保护“按索引打破并列”这一规则。

## 4. scale与对称量化

整数码q需要通过scale恢复到权重尺度。scale可理解为量化格子的步长：若scale=0.5，则q=-2,-1,0,1,2代表-1,-0.5,0,0.5,1。

对称int8教学范围为[-127,127]，零点固定0。令 `scale=maxabs/127`，整数码为 `clip(round(x/scale),-127,127)`，反量化为 `x_hat=q*scale`。全零时scale=1，避免除0；所有码与反量化值都为0。

例如权重 `[254,1,-3]`，scale=254/127=2，比值127、0.5、-1.5，ties-to-even取整后q=(127,0,-2)，反量化=(254,0,-4)。误差不能拿量化码与原值直接相减，必须比较反量化后的同尺度数。

Python本章舍入规则是ties-to-even（中间值取偶数）：

| 比值 | 最近整数码 |
|---|---|
| 0.5 | 0 |
| 1.5 | 2 |
| 2.5 | 2 |
| -0.5 | 0 |
| -1.5 | -2 |
| -2.5 | -2 |

使用 `round(Fraction(...))`直接精确舍入。例x=0.15，最大权重0.3，数学比值 `0.15/(0.3/127)=63.5`，应取64。过早float化可能把半格变成略小于63.5。scale与反量化输出才转float，不给整数判定加epsilon。

## 5. 仿射量化与截断

仿射量化允许非零整数zero_point（简称zp），表示浮点0的整数位置。P075范围[0,255]，本题明确定义：

`q=clip(round(x/scale)+zp,0,255)`；`x_hat=(q-zp)*scale`。

先round，再加零点。scale=0.1、zp=1、x=0.05时，比值0.5先取0再加1，所以q=1、反量化0。若改成round(0.5+1)，ties-to-even会得2，是不同规则。

clip表示超过表示范围就压到端点。scale=1、zp=128、x=200时整数中间值328被截为255，反量化为127。这里误差73，远大于半格0.5，因为输入已经超出可表示范围。

对称int8与仿射uint8各有本题约定。实际框架可能还有按通道scale、不同范围及舍入顺序，不能仅凭“int8”推断全部细节；可核对 [PyTorch量化文档](https://docs.pytorch.org/docs/stable/quantization.html)，具体本题以定义为准。

## 6. 误差与收益怎么核验

误差e=x-x_hat，MSE为 `sum(e*e)/n`，最大绝对误差为 `max(abs(e))`。例如误差[-0.5,-1,1]，MSE=0.75，maxabs=1。MSE有平方单位；最大绝对误差和原权重同单位，两者用途不同。

在最近格点舍入且未截断时，每个点的误差≤scale/2；相应MSE≤scale²/4。P074用maxabs确定范围，因此没有原值越界；P075给定scale可能截断，半格界只适用于未截断项。

真实模型还应测任务精度、保存后文件大小和目标硬件上的速度。剪枝置零可能仍执行稠密乘法，INT8也需要对应算子支持；本章不报告实测加速。PyTorch的[剪枝教程](https://docs.pytorch.org/tutorials/intermediate/pruning_tutorial.html)可用于比较mask与参数重参数化思路，课程练习仍为独立纯Python数值实现。
