# 错题记录：把报错变成下一次可验证的改进

每次只记录一个具体问题：保留输入、期望、实际、原因和最小修复，最后安排不看答案重做。不要只写“粗心”或“不会”。可把新的失败输入放到自己的input.txt，通过题面运行命令复现；不要修改课程cases.json掩盖错误。

## 填好的例子：P001 输出大小写与标点

- 题目：[P001 第一行固定输出](../chapters/01_python/problems/P001/README.md)
- 日期：2026-10-14（维护者演示，不是你的作答记录）
- 输入：空输入。
- 我的临时代码：`print("hello python")`。
- 实际输出：`hello python`。
- 期望输出：`Hello, Python!`。
- 检查结果：答案错误；诊断是 `第 1 行应为 'Hello, Python!'，实际为 'hello python'`。
- 原因：把要求逐字符匹配的固定文字当作含义相近就可以。遗漏H/P的大写、逗号和感叹号。
- 查阅：先展开题面提示1，确认完整字符串；再看提示2确认print与引号；提示3确认无额外输出。
- 最小修复：`print("Hello, Python!")`，保存并运行检查。
- 修复结果：5/5案例通过。该流程在临时副本中完成，正式exercise仍未完成，见[原始演练记录](work/beginner-walkthrough.md)。
- 我能解释的规则：引号本身不打印；print自动换行；大小写、行内空格和标点不能随意改变。
- 重做计划：下一次学习从空文件写出正确的一行，不看答案，执行 `check.py P001`；重做结果由学员填写。

## 可复制模板

把下面内容复制到本文件末尾或自己的笔记，替换方括号内容。

```markdown
### [题号 + 标题] — [日期]

- 题面路径/链接：[填写]
- 当前阶段：读题 / 手算 / 输入解析 / 算法 / 输出 / 环境
- 失败案例名：[填写]
- 完整输入：[贴原输入；空输入写清]
- 手算期望：[填写具体数值、形状或文字]
- 实际输出/完整异常末行：[填写]
- 复现命令：[项目根目录下的命令]
- 原因：[说明哪条规则、哪个变量或哪一步理解错误]
- 读了哪些提示/题解：[如提示1，未看参考解]
- 最小修复：[改了哪一处，为何正确]
- 新增自测边界：[写一个不同输入，不复制原样例]
- 修复检查结果：[通过数/总数或失败诊断]
- 复杂度与局限：[能说明时填写]
- 不看答案重做计划：[下次学习或具体日期]
- 重做结果：[待填写；再次失败则更新原因]
```

常见定位方式：输出行数错误先查print位置；多组数据错误先查状态重置；矩阵结果错误先写形状和手算单元素；算法平票错误先查题面比较键；量化/收敛边界错误先查小数解析和舍入约定。更新[进度表](../PROGRESS.md)时把复习结果对应到题号。
